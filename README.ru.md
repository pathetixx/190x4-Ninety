## Зачем нужен Ninety?

Ninety — нативный клиент для Windows, построенный вокруг sing-box на Tauri 2 и Rust. В одном приложении собраны подписки, отдельные профили, WARP, TUN-режим, правила маршрутизации, DPI-инструменты, логи и управление из трея.

Многие подобные программы генерируют `config.json` и показывают зелёное «Подключено». Ninety следит за тем, что происходит на самом деле: аккуратно запускает и останавливает вспомогательные процессы, восстанавливает системный прокси Windows, показывает фактически выбранную ноду и удаляет временные конфиги.

Чувствительные локальные данные шифруются там, где это позволяет Windows. А когда соединение ломается, приложение показывает диагностику — без гадания по одному статусу.

> Ninety — сетевой клиент, а не гарантия анонимности. Приватность зависит от используемого сервера, провайдера, конфигурации и окружения Windows.

## Что умеет Ninety

| Область | Возможности |
| --- | --- |
| **Режимы подключения** | Локальный прокси, системный прокси Windows и полноценный **VPN · TUN**. Запрос UAC появляется только тогда, когда TUN действительно нужны права администратора. При желании Ninety может запускаться с повышенными правами вместе с Windows. |
| **Источники** | Импорт ссылок на подписки, отдельных конфигураций и `.toml`-профилей TrustTunnel. Ссылку можно вставить из буфера, а поддержку deep links — включить отдельно. |
| **Управление нодами** | Сетка серверов с флагами стран, живая проверка задержки, автоматический выбор, переключение из трея и отображение ноды, которая используется прямо сейчас. |
| **Протоколы** | VLESS, VMess, Trojan, Shadowsocks, Hysteria2, Hysteria, TUIC, AnyTLS, SOCKS, NaiveProxy, TrustTunnel и WARP/WireGuard. |
| **Мосты** | XHTTP работает через xray-core. NaiveProxy и TrustTunnel подключаются через локальные SOCKS-мосты, а центральным маршрутизатором остаётся sing-box. |
| **Маршрутизация** | Обход локальной сети, региональные правила, собственные правила для доменов, IP-адресов и процессов. Есть списки для блокировки рекламы, вредоносных и фишинговых доменов, а также просмотр активных соединений. |
| **Качество соединения** | Проверяется реальная пропускная способность канала, а не один только ping. Ninety может повторить тест, сменить ноду, включить маскировку, заново просканировать WARP или предложить переподключение. |
| **DPI-инструменты** | Отдельный раздел с инструментами совместимости, обновлением стратегий и списков, удалением драйвера и автоматическим исключением адресов VPN-нод. |
| **Приватность** | Строгий TUN закрепляет одну ноду, убирает прямые исключения и удерживает сессионную WFP-блокировку при падении туннеля. После подключения Ninety также умеет запускать бесплатный Mullvad Browser. |
| **Интерфейс** | Управление из трея, обновления внутри приложения, восстановление сессии после обновления, темы, первоначальная настройка, 15 языков и RTL-вёрстка для فارسی / العربية. |

## Поддерживаемые протоколы и транспорты

**Протоколы:** VLESS · VMess · Trojan · Shadowsocks · Hysteria2 · Hysteria · TUIC · AnyTLS · SOCKS · NaiveProxy · TrustTunnel · WARP/WireGuard

**Транспорты и опции:** Reality · TLS с uTLS-отпечатками · XHTTP · WebSocket · gRPC · HTTP/2 · HTTPUpgrade · QUIC · mKCP · TCP · TLS-фрагментация · padding · mixed-case SNI · mux

NaiveProxy и TrustTunnel запускаются через собственные локальные клиенты и передают трафик в sing-box по SOCKS-мостам. Для XHTTP при необходимости используется xray-core.

В интерфейсе всё это выглядит одинаково: один источник, одна кнопка подключения и понятное текущее состояние.

## Установка

Скачайте последнюю версию из раздела [**Releases**](https://github.com/pathetixx/190x4-Ninety/releases):

- `.exe` — установщик NSIS.
- `.msi` — пакет MSI.

Требования: **Windows 10 / 11 x64**.

Обновления скачиваются внутри приложения. Если VPN уже подключён, Ninety может проверить и загрузить новую версию через активный туннель.

## Быстрый старт

1. Откройте Ninety и нажмите **+**.
2. Вставьте ссылку на подписку или отдельную конфигурацию: `vless://`, `vmess://`, `trojan://`, `hysteria2://`, `tuic://`, `naive+https://`, `tt://` и так далее.
3. Выберите режим:
   - **Системный прокси** — используется по умолчанию, не требует прав администратора и подходит для браузеров и многих Windows-приложений.
   - **Прокси** — запускает локальный SOCKS/HTTP-прокси на `127.0.0.1`. Нужные приложения настраиваются вручную.
   - **VPN · TUN** — направляет системный трафик через туннель и требует запуска с повышенными правами.
4. Нажмите на центральный диск, чтобы подключиться. Повторное нажатие отключает соединение.

Если подключение не поднялось, сначала откройте **Логи**. Там видны ошибки запуска, мостов и маршрутизации — искать файлы вручную в папках приложения не придётся.

## Безопасность и приватность

Ninety открыт по исходникам, но работает с компонентами, которые меняют сетевые настройки Windows.

- Импортированные профили и ссылки на подписки могут содержать логины, токены и другие данные для доступа.
- Перед публикацией удаляйте секреты из логов и скриншотов.
- В установленной Windows-сборке живые профили и подписки, WARP-ключи и recovery-снимки хранятся в versioned Rust/DPAPI-envelopes; старые WebView-ключи удаляются после успешной миграции. Backend-хранилище Full Portable по умолчанию работает в режиме `NoPersistentSecrets`; после явного пароля используется Argon2id + XChaCha20-Poly1305. Пароль живёт только в памяти процесса и не записывается в `NinetyData`. Если Portable нельзя разблокировать или миграция не удалась, legacy-копия WebView сохраняется как fallback. Отдельный режим `PlaintextExplicitlyConfirmed` доступен только после явного подтверждения хранения backend-секретов без шифрования.
- TUN-режим, DPI-инструменты и kill switch меняют системную сеть. Перед включением проверьте выбранные настройки.
- Ninety не гарантирует анонимность.

Подробнее о хранении локальных данных написано в разделе [Privacy](./docs/privacy.md). Уязвимости следует отправлять по правилам из [SECURITY.md](./SECURITY.md).

## Архитектура

Интерфейс Ninety работает в Tauri WebView и общается с Rust-бэкендом через команды и события Tauri.

Бэкенд управляет sing-box, вспомогательными процессами, состоянием WARP/WireGuard, системным прокси Windows, TUN-режимом, kill switch, обновлениями, логами и очисткой временных данных.

Подробная схема проекта находится в документе [Architecture](./docs/architecture.md).

## Сборка из исходников

Понадобятся:

- стабильная версия Rust;
- Node.js 20.19 или новее; рекомендуется Node.js 22 LTS;
- инструменты сборки MSVC;
- Windows для полноценной сборки Tauri-приложения.

```powershell
npm run preflight
npm install
npm run tauri dev
npm run tauri build
```

`sing-box` и `xray-core` CI собирает из исходников по закреплённым тегу и коммиту, а NaiveProxy, TrustTunnel и `wintun.dll` скачивает по закреплённым версии и SHA-256. Настройка находится в [`.github/workflows/build.yml`](./.github/workflows/build.yml).

Для обычных проверок во время разработки:

```powershell
npm run lint
npm test
```

Полные проверки Rust и Tauri лучше запускать в Windows CI. Локально они потребуют заранее подготовленного Windows-окружения со всеми инструментами и зависимостями.
