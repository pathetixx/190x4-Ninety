## Short description for the application

Ninety is an open-source Windows desktop networking client built with Tauri 2
and Rust. It manages user-supplied VPN/proxy profiles, local/system-proxy and
TUN modes, routing rules, connection diagnostics, WARP profiles and an optional
DPI compatibility module. It does not provide a hosted VPN service, telemetry,
remote administration, vulnerability scanning or exploit functionality.

## Security-sensitive functionality disclosure

The optional DPI compatibility module uses the open-source `winws` and
WinDivert projects to adjust the packet representation of traffic generated by
the local user. It does not scan other systems, discover vulnerabilities,
deliver payloads, obtain unauthorized access or disable Windows endpoint
security. The feature is visible in the UI, user-controlled and includes driver
cleanup/uninstall handling.

The application also supports TUN mode, Windows system-proxy changes and an
optional kill switch. These system changes are user-selected and documented.
Ninety restores or removes its runtime networking state during disconnect,
shutdown and uninstall flows.

## Signing request

The project requests Authenticode signing for artifacts built from versioned
source tags:

1. `Ninety.exe`, built from this repository;
2. the NSIS installer containing the already signed `Ninety.exe`;
3. the MSI package containing the already signed `Ninety.exe`.

Bundled upstream networking engines, DLLs and drivers must be excluded from the
Ninety signing directive. The build pins source revisions or verifies release
downloads using SHA-256. Upstream components retain their own licenses and
signatures, if provided by upstream.

Every release signing request will require manual approval. The signed
installers will be returned to the same GitHub Actions run, verified, signed
again with the separate Tauri updater key and only then published.

## Maintainer actions required in SignPath

1. Open <https://signpath.org/apply.html> and submit the project application.
2. Enable multi-factor authentication for GitHub and SignPath accounts.
3. After acceptance, install the SignPath GitHub App for this repository.
4. Create or accept the SignPath project, trusted GitHub build-system link,
   artifact configurations and production signing policy.
5. Keep the organization ID, API token and policy identifiers out of source
   control. Store the API token only as a GitHub Actions secret.

The CI workflow must not be enabled until SignPath has supplied the actual
organization ID, project slug, signing-policy slug and artifact-configuration
slugs.
